# Deployment Guide - Blog Platform

## Railway Deployment

### Prerequisites
- GitHub account with repository access
- Railway.app account (free tier available)
- Cloudinary account for media storage (free tier available)

---

## Step 1: Cloudinary Setup (Media Storage)

**Why Cloudinary?** Stores all user uploads (images, attachments) in the cloud. Your local Render instance used it, and you can create a new free account or reuse existing credentials.

### Option A: Create New Cloudinary Account
1. Go to https://cloudinary.com/users/register/free
2. Sign up with email
3. In dashboard, find your **API Credentials**:
   - Copy: `Cloud Name` → `CLOUDINARY_CLOUD_NAME`
   - Copy: `API Key` → `CLOUDINARY_API_KEY`
   - Click "Generate" next to API Secret → `CLOUDINARY_API_SECRET`

### Option B: Use Existing Render Cloudinary
**You cannot retrieve** Cloudinary keys from Render's dashboard (they're secrets). If you remember creating them:
- Check your password manager/notes for saved credentials
- Or create a new free Cloudinary account (better for fresh start)

## Step 2: Railway Project Setup

### 2.1 Create New Railway Project
1. Log into https://railway.app
2. Click **"New Project"** → **"Deploy from GitHub"**
3. Authorize Railway with GitHub
4. Select your **blog_platform** repository
5. Railway auto-detects Django and provisions:
   - PostgreSQL database
   - Redis cache (optional, but recommended)

### 2.2 Configure Environment Variables
In Railway dashboard, go to **"Variables"** tab and add these:

```
# Django Settings
SECRET_KEY=<generate-secure-key>
DEBUG=False
ALLOWED_HOSTS=your-project.railway.app,*.railway.app

# Database (Railway auto-generates this, leave commented or use Railway's DATABASE_URL)
DATABASE_URL=<auto-generated-by-railway>

# Redis (Railway auto-generates if you add Redis add-on)
REDIS_URL=<auto-generated-by-railway>

# Cloudinary
CLOUDINARY_CLOUD_NAME=<your-cloud-name>
CLOUDINARY_API_KEY=<your-api-key>
CLOUDINARY_API_SECRET=<your-api-secret>

# Superuser (auto-created during build)
SUPERUSER_USERNAME=admin
SUPERUSER_EMAIL=admin@blogplatform.com
SUPERUSER_PASSWORD=<secure-password>

# Security
SECURE_SSL_REDIRECT=True
SESSION_COOKIE_SECURE=True
CSRF_COOKIE_SECURE=True
```

### Generate Secure SECRET_KEY
Run locally:
```bash
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```
Copy output to `SECRET_KEY` variable.

### 2.3 Add PostgreSQL Add-on
1. In Railway, go to **"Add New"** → **"Database"** → **"PostgreSQL"**
2. Railway auto-generates `DATABASE_URL` environment variable
3. Repeat for **Redis** if needed (for caching)

### 2.4 Configure Procfile (if not auto-detected)
Create `Procfile` in project root:
```
web: gunicorn blog_platform.wsgi:application --bind 0.0.0.0:$PORT
```

---

## Step 3: Deploy

1. **Trigger Deploy**: Push to main/dev branch
   ```bash
   git push origin dev
   ```
2. Railway automatically deploys on push
3. Monitor build logs in Railway dashboard

### Build Issues?
- Check **"Logs"** tab for errors
- Common: `CLOUDINARY_API_SECRET` missing → add to variables
- Database connection error → verify `DATABASE_URL` exists

## Step 4: Load Sample Data

After deployment succeeds, populate the database with sample users and articles.

### Option A: Admin Panel (Manual)
1. Open `https://your-project.railway.app/admin`
2. Login with superuser (from `SUPERUSER_USERNAME` & `SUPERUSER_PASSWORD`)
3. Create users, profiles, and bulletins manually through Django admin

### Option B: Management Command (Automated)
Create `accounts/management/commands/populate_sample_data.py`:

```python
from django.core.management.base import BaseCommand
from django.contrib.auth.models import User
from accounts.models import Profile
from content.models import Bulletin, Article

class Command(BaseCommand):
    help = 'Populate database with sample data for demonstration'

    def handle(self, *args, **options):
        # Create sample readers
        for i in range(3):
            username = f'reader{i+1}'
            if not User.objects.filter(username=username).exists():
                user = User.objects.create_user(
                    username=username,
                    email=f'{username}@example.com',
                    password='TestPassword123!'
                )
                Profile.objects.create(
                    user=user,
                    role='reader',
                    biography=f'Reader {i+1} passionate about technology and writing.'
                )
                self.stdout.write(f'Created reader: {username}')

        # Create sample writers with articles
        for i in range(2):
            username = f'writer{i+1}'
            if not User.objects.filter(username=username).exists():
                user = User.objects.create_user(
                    username=username,
                    email=f'{username}@example.com',
                    password='TestPassword123!'
                )
                profile = Profile.objects.create(
                    user=user,
                    role='writer',
                    biography=f'Professional writer with expertise in various topics.'
                )

                # Create bulletin
                bulletin = Bulletin.objects.create(
                    profile=profile,
                    title=f'{user.first_name or username}\'s Bulletin',
                    slug=f'{username}-bulletin',
                    description=f'A collection of thoughtful articles by {username}.'
                )

                # Create sample articles
                for j in range(2):
                    Article.objects.create(
                        bulletin=bulletin,
                        title=f'Article {j+1} by {username}',
                        content=f'<p>This is sample article content {j+1} written by {username}.</p>',
                        status='published',
                        visibility='public',
                        evaluation='approved'
                    )

                self.stdout.write(f'Created writer: {username} with bulletin and articles')

        self.stdout.write('Sample data population completed!')
```

### Run Command
```bash
# Locally (before pushing)
python manage.py populate_sample_data

# On Railway (via console)
# Go to Railway dashboard → your project → Console tab
python manage.py populate_sample_data
```

## Troubleshooting

### "502 Bad Gateway" or "Application Error"
1. Check **Logs** in Railway dashboard
2. Common causes:
   - Missing environment variables (especially `SECRET_KEY`, `CLOUDINARY_*`)
   - Database migration failed
   - Django check errors

### Fix: Re-run Build
```bash
# Force rebuild in Railway dashboard:
# Settings → Redeploy
```

### "No such table" Database Errors
Migrations didn't run. In Railway console:
```bash
python manage.py migrate
python manage.py populate_sample_data
```

### Static Files Not Loading
Ensure `STATIC_URL = '/static/'` in settings.py. Railway uses WhiteNoise for static serving (built into settings).

### Cloudinary Upload Failures
- Verify `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` are correct
- Test in Django shell:
  ```python
  python manage.py shell
  from cloudinary.uploader import upload
  result = upload('your_file.jpg')
  print(result)
  ```

## Database Backup & Recovery

### Backup PostgreSQL
Railway provides automated daily backups. To export:
1. Connect via Railway console
2. Use `pg_dump`:
   ```bash
   pg_dump $DATABASE_URL > backup.sql
   ```

### Restore
```bash
psql $DATABASE_URL < backup.sql
```

## Post-Deployment Monitoring

### Enable Sentry for Error Tracking (Optional)
1. Sign up at https://sentry.io
2. Create Django project
3. Add to requirements.txt:
   ```
   sentry-sdk
   ```
4. Add to `settings.py`:
   ```python
   import sentry_sdk
   sentry_sdk.init(dsn="your-sentry-dsn", debug=False)
   ```

### View Logs
- Railway dashboard → Logs tab (real-time)
- Filter by severity (Errors, Warnings)
